# QQ Codex 客户端设计规格

## 目标

构建一个可在 Windows 上日常使用的独立 Codex 桌面客户端。客户端采用 QQ 2009 经典视觉语言，但不牺牲编码工作效率。首版必须支持本地项目、Codex 任务、流式消息、文件修改、Diff、命令执行、审批和历史恢复。

首版不追求与官方客户端全部功能一比一对齐。自动化、浏览器、语音、连接器和其他高级能力不在本次范围内。

## 方案选择

考虑了三条路线：

1. Electron + React + TypeScript：本地系统能力完整，Node 生态可直接承载 Codex 适配层，开发与调试速度快。
2. Tauri + React + Rust：安装包更小，但需要额外维护 Rust 桥接，首版交付速度较慢。
3. 浏览器前端 + Node 本地服务：界面开发最快，但桌面窗口、文件系统、终端进程和本地协议的体验较弱。

采用方案 1。Electron 主进程负责系统能力和 Codex 进程，React 渲染进程只负责界面，通过受限 IPC 调用后端服务。

## 视觉与布局

视觉基准为 QQ 2009：天蓝到深蓝的标题栏渐变、浅蓝高光、企鹅头像、圆角工具按钮、好友分组、聊天气泡、在线状态和经典 Windows 桌面软件密度。避免把怀旧风做成不可读的像素玩具；正文、代码和 Diff 保持现代等宽字体与清晰对比度。

主窗口采用混合式三段布局：

- 左栏宽约 248 像素，顶部展示用户头像、在线状态和搜索框，下方按“最近任务”和“本地项目”分组，形态类似 QQ 好友列表。
- 中栏为主要聊天工作区，包含任务标题栏、消息流、工具调用与审批卡片、输入区和经典 QQ 工具栏。
- 右栏宽约 380 像素，以标签切换“文件”“修改”“终端”，可折叠以给聊天区更多空间。
- 窗口宽度不足时，右栏变为覆盖式抽屉；左栏保持可收起，聊天区永远是主区域。

## 架构与组件边界

### Electron 主进程

负责创建窗口、保存窗口状态、选择工作目录、启动和停止 Codex App Server、管理终端子进程，以及将系统事件转换为稳定的内部事件。

### Codex 适配层

封装 App Server 的初始化、任务创建、恢复、回合启动、流式事件、取消、审批和错误映射。UI 不直接依赖 App Server 原始协议，以便协议变化时只修改适配层。

### IPC 合同

preload 只暴露白名单接口：工作区、任务、消息、审批、文件、Diff、终端和应用设置。每个请求与事件均有 TypeScript 类型和运行时校验。渲染进程不能直接访问 Node、文件系统或任意进程执行接口。

### React 界面

按领域拆分为 Shell、BuddyList、Conversation、ApprovalCard、Composer、Inspector 和 StatusBar。状态层保存可序列化的界面状态；Codex 事件经统一 reducer 更新，避免组件各自解释协议。

### 本地存储

仅保存界面偏好、最近工作区、任务索引和窗口状态。Codex 对话实体由 App Server 管理，不复制完整历史。敏感令牌不写入前端存储。

## 数据流

启动时，主进程创建 App Server 会话并完成初始化。用户选择项目后，客户端加载该项目关联的任务索引。新建任务会创建 thread；发送消息会启动 turn；流式事件被规范化后通过 IPC 推送给 React。文件修改或命令执行需要审批时，消息流插入审批卡片，用户选择同意或拒绝后由适配层回复 App Server。

关闭窗口前，客户端保存窗口与最近工作区状态，并优雅停止终端与 App Server 子进程。再次打开时可以恢复已有任务，但不会自动执行未完成的高风险操作。

## 错误与安全

- 找不到 Codex CLI：显示安装检查页和实际检测路径，不进入伪在线界面。
- App Server 启动或初始化失败：显示可复制的错误摘要和重试按钮。
- 任务流中断：保留已收到内容，标记断线，并允许重试或新开回合。
- 工作区失效：保留任务记录，但禁用发送与文件操作，提示重新选择目录。
- 审批超时或进程退出：审批卡片转为终止状态，不重复提交。
- 渲染进程启用 context isolation，关闭 node integration；所有路径与命令操作都经过主进程校验。

## 首版功能

1. Windows 桌面窗口与 QQ 2009 主题。
2. 选择、保存和切换本地项目。
3. 创建、选择、恢复和重命名任务。
4. 发送消息、查看流式响应、停止当前回合。
5. 展示工具调用、命令执行和文件修改事件。
6. 同意或拒绝需要审批的操作。
7. 文件树、Diff 查看器和终端输出面板。
8. 连接状态、错误状态和重试流程。
9. 基础键盘操作、可读焦点状态和减少动画设置。

## 测试与验收

单元测试覆盖协议事件规范化、reducer、任务索引、路径校验和审批状态机。组件测试覆盖消息、审批、空状态和错误状态。集成测试使用假的 App Server 进程验证初始化、流式回合、审批与断线。桌面冒烟测试验证窗口启动、工作区选择和三个主面板切换。

验收必须通过以下真实链路：选择本地仓库，创建任务，发送请求，收到流式回复，审批一次文件修改，查看 Diff，审批一次命令执行，关闭并重新打开客户端，恢复同一任务。若本机 App Server 接口与文档存在差异，必须显示明确的兼容性错误，不能用静态数据冒充成功。

## 非目标

首版不实现多人协作、移动端、云端同步、自动化调度、浏览器控制、语音、应用连接器、插件市场和官方客户端全部设置项。
